# Покрытие HTTP для модели WAF

Эта карта определяет группы для сравнения поколений. Владельцы правил и модели проверяют классы на отложенной выборке. Для измерения ложных блокировок по каждой зоне есть обычные запросы в `model/legitimate-http/`.

| Зона HTTP | Какие классы учитывать | Обычные запросы для проверки |
| --- | --- | --- |
| Путь | Обход каталогов, обращение к чувствительным ресурсам | Кириллица, пробелы в имени файла, точки в идентификаторе |
| Query | SQL-инъекции, XSS, инъекции команд и шаблонов | Апостроф в имени, поиск по C++, несколько тегов |
| Заголовки | Признаки инъекций в значениях заголовков | Список языков, ETag, диапазон байтов |
| Cookie | Признаки инъекций в значениях cookie | Предпочтения интерфейса и сохранённые фильтры |
| JSON | Инъекции в строковых полях JSON | Вложенные поля, массивы, Markdown, Unicode и числовые значения |
| Form | Инъекции в полях формы | Контактная форма, повторяющиеся поля и параметры корзины |
| Multipart | Инъекции в полях формы и обработка метаданных файла | Поле с описанием и загрузка простых текстовых файлов |
| XML | Контроль обработки XML и признаки внешних сущностей | Небольшой каталог, запись инвентаря и sitemap |

## Что известно об оценке

В документации предыдущих прогонов есть результаты по классам. Матрица «класс × зона запроса» нужна для следующей оценки. Для поколения 3 сводка `coverage.json` считает наблюдения по зоне, классу, метке и выборке. Пустая ячейка означает отсутствие измерения. Сравнивайте обнаружение и ложные блокировки отдельно, а ошибки обработки учитывайте отдельным счётчиком. Держите варианты одного сценария в одной группе и используйте одну проверочную выборку для обоих поколений.

Проверки разграничения доступа и бизнес-логики выполняются в приложении. Обработка неоднозначного HTTP относится к контракту прокси и upstream. Проверку файлов на вредоносное содержимое выполняет File Security, если он включён. Эти результаты следует показывать отдельно от ML-оценки open-appsec.
