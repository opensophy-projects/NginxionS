# Модель WAF NginxionS: обучение, проверка, выпуск

**Модель в образе** — продвинутая модель: `openappsec/agent/components/security_apps/waap/resources/waap.data`
кладётся в исходники агента при сборке образа `nginxions-openappsec` вместо базовой модели open-appsec (как велит README
модели). Лицензия модели — внутри файла (ключ `license`), она сохраняется и в моделях, обученных из неё.

Поверх неё NginxionS обучает свою модель: на открытых размеченных данных, в своём CI, на настоящем агенте. Готовая
модель загружается в упаковке `open-appsec-advanced-model.tgz` через **WAF → Агент → Модель → Загрузить**
(`PUT /api/nginxions/waf/agent/model`). Архив должен содержать один обычный файл `waap.data` в корне. Перед заменой
NginxionS проверяет целостность архива и читает JSON модели с сигнатурами и оценками (до 128 МиБ после распаковки).
«Удалить модель» возвращает модель образа. Загрузка и запуск работают локально.

## Как устроена модель open-appsec

Модель — один файл `/etc/cp/conf/waap/waap.data` агента:

- **сигнатуры** (`waap_signatures`): около 1 200 регулярных выражений. Они превращают значение запроса (параметр,
  заголовок, тело, cookie) в список **ключевых слов**: `<script`, `union`, `../`, `$(`…;
- **оценки** (`waap_scores`): вес каждого ключевого слова и пары соседних слов.

Базовая модель open-appsec (из исходников) считает оценку значения по счётчикам: сколько раз слово встречалось в
атаках и в легитимном трафике. Продвинутая модель — **разреженная логистическая
регрессия** с признаками «есть/нет»:

```
оценка = 10 · sigmoid(intercept + log_nnz_coef · ln(n + 1) + Σ coef(признак))
```

где признаки — ключевые слова значения и их пары, `n` — их число. Слово, которого нет в модели, весит 0,3, пара —
0,8. Агент поддерживает такой формат сам (`isLinModel` в `ScoreBuilder`), поэтому **наша модель не требует правок
агента**: мы обучаем коэффициенты и записываем их в тот же `waap.data`. Сигнатуры остаются те, что в модели образа.

Решение о блокировке агент принимает по **итоговой** оценке: оценка значения × поправка на **репутацию
источника** × поправка обучения (`D2Main.cc`), затем сравнение с порогом уверенности политики (`high`,
`critical`…).

## Что мы измерили

> Это измерение — до того, как в образ встала продвинутая модель: «штатная» здесь — базовая модель open-appsec.
> В следующих сравнениях используйте одну зафиксированную проверочную выборку и продвинутую модель в качестве базовой.

Первая модель NginxionS (`training.yml`, 15% легитимного набора, политика `high`, у каждого запроса свой источник).
Отложенная часть — 40 665 легитимных запросов сайтов, которых модель не видела, и 22 072 атаки; решения
настоящего агента:

| | Штатная модель | Модель NginxionS |
|---|---|---|
| атаки заблокированы | 99,37% | 99,42% |
| легитимные пропущены | 73,99% | **99,52%** |
| ложные блокировки | 10 575 | **196** |
| пропущенные атаки | 139 | 128 |
| сбалансированная точность | 86,68% | **99,47%** |

Штатная модель блокирует каждый четвёртый обычный запрос реального сайта; наша — один из двухсот, и атак ловит
не меньше. Совпадение оценок агента и тренера — 144 548 из 144 548 значений.

Где новая модель слабее штатной (по категориям, это — работа следующих версий): SQLi 96,96% против 99,66%,
Shellshock 83% против 100% (в проверке всего 6 таких атак). Безобидные «похожие на атаки» тексты mgm модель
пропускает чаще штатной (SQLi 50% против 0%, XXE 50% против 0%), но этих примеров единицы — нужны свои случаи
в `model/cases/`.

## Цикл обучения

Workflow **Training** читает текущий checkout, в том числе ветку `work`. Обычный прогон собирает проверенные
легитимные случаи в артефакт `waf-http-coverage`. Сценарии по зонам запроса перечислены в [карте HTTP](../training/HTTP-COVERAGE.md).

Для ручного обучения укажите `feature_run` — номер успешного прогона этого репозитория с артефактом
`waap-features`. В артефакте нужны два файла:

- `model.sha256` — SHA-256 `waap.data`, с которой получены наблюдения.
- `observations.jsonl` — по одному наблюдению на запрос. Поля `id`, `group`, `source`, `category` — короткие
  идентификаторы. `surface` — зона HTTP из карты. `label` принимает 0 для обычного запроса и 1 для атаки.
  `blocked` — решение базового агента. Каждый элемент `values` содержит массивы `keywords`, `combinations`
  из словаря модели и числовой `score` от 0 до 10. Варианты одного сценария и наблюдения одного сайта
  указывайте с общей группой.

`model/feature_dataset.py` проверяет согласованность файла, сохраняет целые группы в одной выборке и считает
число примеров по классам и зонам. `model/train.py` подбирает веса и порог на обучающей части. Штатная версия
модели служит начальным приближением. Метрики кандидата на отложенной выборке попадают в карточку.

Артефакт `waf-model-offline-candidate` содержит файл модели, карточку и `coverage.json`. Для выпуска нужна
отдельная оценка на агенте с тем же контрольным набором. [Упаковка проверенного поколения 3](../training/README.md).

## Когда модель можно выпускать

### Что уже проверяет стенд

`scripts/train-model.sh` использует отдельный стек open-appsec и тестовый upstream. Базовая модель — `waap.data`,
скопированный из контейнера агента. Для поколения 3 сравнение должно начинаться с [закреплённой модели поколения 2](../training/generations/2/source.json).
Оценка работающего агента и приготовление [офлайн-кандидата](#цикл-обучения) — отдельные прогоны. Скрипт стенда
формирует свой кандидат в том же цикле, а оценщик также умеет читать ранее записанные результаты двух прогонов.

Агент пишет один набор признаков и оценку на каждое разобранное значение. Тестовый клиент записывает HTTP-ответ
и идентификатор каждого запроса. `model/evaluate.py` связывает эти данные по идентификаторам отложенной выборки.
Служебные пробы остаются в журнале стенда и исключаются из расчёта совпадения оценок.

### Критерии выпуска

Все условия сразу, на проверочной части, по решениям **настоящего агента**.

- **осмотр**: каждый проверочный запрос, в котором агент нашёл ключевые слова с моделью образа, дошёл до агента
  и с новой (≥ 99,5%). После перезапуска агента рабочие процессы nginx подключаются к нему по одному, и не
  подключившийся пропускает запросы без проверки (fail-open); стенд ждёт, пока атаки блокируются во всех, но
  проверка ловит и то, что он пропустил;
- **ответы**: сравниваются одни и те же запросы с пригодным ответом обеих моделей. На этом стенде `2xx` означает
  пропуск, `403` — блокировку. Таймаут, `5xx` и другие статусы учитываются отдельно. Пропущенных пар может быть до 0,1%,
  а среди оставшихся должны быть и атаки, и обычные запросы;
- сбалансированная точность (среднее «атаки заблокированы» и «легитимные пропущены») не ниже модели образа;
- доля пропущенных легитимных запросов не ниже модели образа больше чем на 0,2 п.п.;
- доля заблокированных атак не ниже модели образа больше чем на 0,5 п.п.;
- **совпадение оценок**: оценка, которую агент поставил каждому значению с новой моделью, равна оценке, которую
  считает `model/waapmodel.py` по тем же признакам (≥ 99,9% значений с точностью 0,001). Если нет — агент читает
  модель не так, как её обучали, и цифры выше ничего не гарантируют для следующей модели.
- **совпадение модели**: SHA-256 `waap.data`, загруженного в агент, совпадает с SHA-256 файла кандидата.

Оценщик `model/evaluate.py` записывает итог, метрики и SHA-256 обеих моделей с агента в `metrics.json`.
Для упаковки передайте этот отчёт вместе с `out/waap.data` и `out/model-card.json`. Упаковщик поколения 3 сверяет
SHA-256 базы из отчёта с манифестом поколения 2.

## Выпуск

[Каталог поколений](../training/README.md) содержит закреплённый архив модели поколения 2 и инструкции по
упаковке прошедшего оценку кандидата поколения 3. Отчёт `metrics.json` содержит SHA-256 файла, прочитанного при
оценке. Установочный архив и карточку можно прикрепить к релизу GitHub после проверки. Администратор ставит модель
в **Агенты → open-appsec → Агент → Модель**. Чтобы вернуться к модели образа, удалите загруженную модель там же.

## Чего модель не делает

- **Ноль риска недостижим.** Гарантия процесса другая: каждая выпущенная модель не хуже предыдущей на
  фиксированной проверке, а каждый найденный обход становится случаем в `model/cases/` и проверяется в каждом
  следующем обучении.
- Модель видит только то, что нашли сигнатуры. Атака, в которой агент не нашёл ни одного ключевого слова, для
  любой модели невидима: таких атак `model-card.json` показывает отдельно (`attacks_without_keywords`). Это
  работа для сигнатур, разбора запроса агентом (сжатое тело, необычные кодировки) и других слоёв: CrowdSec,
  схема OpenAPI, правила nginx.
- Метрики WAF Comparison Project и наши нельзя сравнивать напрямую: WCP шлёт все запросы с одного адреса, и на
  итог влияет репутация источника; у нас у каждого запроса свой источник.

## Локальная проверка

```bash
python3 -m unittest discover -s model
mkdir -p model-work
python3 model/check_verdict_cases.py model/verdict-cases.txt --requests-out model-work/http-cases.jsonl
```

Команда проверяет примеры вердиктов и экспортирует размеченные обычные запросы в JSONL. Формат записей и расположение отчётов CI описаны в [карте покрытия HTTP](../training/HTTP-COVERAGE.md).
