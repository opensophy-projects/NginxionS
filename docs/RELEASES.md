# Версии и обновления NginxionS

Версия текущей сборки видна внизу бокового меню. Стабильный релиз отображается как `V1.0.0`, сборка ветки `work` — по хешу коммита. Откройте версию и нажмите «Проверить обновления», чтобы запросить последний стабильный релиз с GitHub. Установка без интернета продолжает работать, а панель показывает состояние проверки.

## Стабильная установка

Для новой установки Linux amd64 скачайте исходники нужного GitHub-релиза и запустите установщик из распакованного каталога.

```bash
sudo ./scripts/install.sh --version V1.0.0
```

Для установки с поддержкой автоматических обновлений используйте `--with-updater` на Linux amd64 с systemd и curl. Обновлятор устанавливается в `/opt/nginxions`. В боковом меню администратор может включить автоматическую установку. Таймер проверяет релизы раз в сутки после включения в панели.

Для уже запущенной установки Compose обновите файлы развёртывания из нужного релиза, сохранив локальные значения в `deploy/.env`. Укажите версию в `NGINXIONS_VERSION`, затем выполните `docker compose -f deploy/compose.yaml up -d --pull always`. Для установки из архива без интернета следуйте [инструкции офлайн-бандла](OFFLINE.md).

## Что делает автообновление

Обновлятор загружает оба образа по дайджестам из GitHub-релиза и запускает существующую конфигурацию Compose. Совместимы более новые стабильные версии той же основной ветки, у которых совпадают файлы развёртывания и версии PostgreSQL, CrowdSec и ClamAV. Для смены основной версии, изменения этих файлов или перехода с `develop` обновите развёртывание вручную по инструкциям релиза.

Версия сохраняется в `deploy/.env` после запуска и проверки готовности стека. При сбое обновлятор пробует запустить прежние образы с сохранёнными томами. Миграции данных этим действием не откатываются. Журнал находится в `journalctl -u nginxions-update.service`. Удаление установки также удаляет таймер.

## Выпуск версии

Создайте и отправьте стабильный Git-тег вида `V1.0.0` на коммите `work`. После CI и проверки офлайн-установки workflow публикует оба образа с тегами `V1.0.0`, `1.0.0` и `latest`. Формат с нижним `v` также поддерживается. Затем GitHub Actions создаёт GitHub Release с тем же номером, офлайн-архивом Linux amd64, контрольной суммой и манифестом обновления. Для обоих образов полный стек публикуется для Linux amd64.
